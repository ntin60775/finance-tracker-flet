# Audit Action Plan (2026-02)

План закрытия недостатков проекта после технического и продуктового аудита.

## Цели

1. Снять разрыв между обещанной и фактической функциональностью.
2. Повысить эксплуатационную надежность финансовых сценариев.
3. Улучшить UX ежедневной работы пользователя с долгами/платежами/план-факт.
4. Повысить инженерную зрелость: качество кода, CI, наблюдаемость.

## Приоритеты

- P0 — критично, влияет на доверие и риск потери данных.
- P1 — высокий приоритет, улучшает стабильность и поддержку.
- P2 — средний приоритет, повышает удобство и масштабируемость.

## P0 (критично)

### 1) Реальный экспорт/импорт данных

- Статус: API временно отключен (NotImplementedError).
- Трекер: `https://github.com/ntin60775/finance-tracker-flet/issues/4`.
- Минимальный результат:
  - экспорт полного снимка домена в JSON;
  - импорт со строгой валидацией версии/структуры/UUID;
  - атомарность (транзакция БД, rollback при ошибке);
  - отчет по результатам импорта (добавлено/пропущено/конфликты).

### 2) Честность документации и UX-сообщений

- Не заявлять как "готово", пока фича в разработке.
- Явно указывать fallback: резервное копирование `.finance_tracker_data/finance.db`.

## P1 (высокий приоритет)

### 3) Покрытие тестами и quality gates

- Ввести поэтапный coverage gate в CI (например, старт 65%, затем 70/75/80).
- Добавить отдельный job для `pip-audit` и регулярно обновлять toolchain.
- Зафиксировать policy: новые сервисы/модули без тестов не принимаются.

### 4) Рефакторинг крупных модулей

Приоритетные кандидаты:
- `views/loan_details_view.py`
- `views/transaction_history_view.py`
- `services/loan_payment_service.py`
- `components/transactions_panel.py`

Цель: декомпозиция на меньшие компоненты с единичной ответственностью.

### 5) Ошибки и наблюдаемость

- Сократить количество широких `except Exception` на доменные исключения.
- Стандартизировать коды ошибок/контекст логов по операциям денег/долгов.
- Добавить единый журнал критических доменных событий (удаление, перенос долга, импорт).

## P2 (средний приоритет, продукт)

### 6) UX: рабочий экран "Сегодня"

- Баланс на сегодня, обязательные платежи, просрочки, кассовый риск (7/30 дней).
- Быстрые действия: добавить транзакцию, отметить оплату, открыть риск.

### 7) UX: guided-flow для сложных операций

- Мастер для досрочного погашения и передачи долга.
- Предпросмотр финансового эффекта перед подтверждением.

### 8) План-факт и аналитика

- Доработать DateRangePicker в план-факт экране.
- Добавить сценарии сравнения периодов и сохранение пользовательских фильтров.

## Предлагаемая последовательность релизов

### Release A (stability)

- P0.1, P0.2, P1.3

Критерий приемки:
- Пользователь не видит ложных обещаний функционала;
- CI включает lint/test/security шаги;
- Документация соответствует факту.

### Release B (data safety)

- P0.1 полностью + интеграционные round-trip тесты

Критерий приемки:
- Экспорт/импорт работают end-to-end на чистой и непустой БД.

### Release C (architecture + UX)

- P1.4, P1.5, P2.6

Критерий приемки:
- Уменьшена сложность ключевых модулей;
- Сокращено число аварийных сценариев;
- Улучшен ежедневный UX.

## Definition of Done для задач плана

- Код покрыт тестами (unit/integration, где применимо).
- `ruff check src tests` — без ошибок.
- `pytest tests/ -q` — зеленый.
- Документация обновлена в том же PR.
