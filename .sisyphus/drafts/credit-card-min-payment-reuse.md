# Draft: Учет кредиток с повторным использованием лимита

## Requirements (confirmed)
- Пользователь ведет около 10 кредитных карт.
- Для части карт после внесения минимального платежа доступный лимит можно снова тратить.
- Для другой части карт повторное использование после платежа недоступно (только погашение).
- Нужно понять, поддерживает ли это текущая система, и если нет — какие изменения нужны.
- Не требуется детальный учет расходов по кредитке в момент покупки.
- Все платежи по кредиткам являются подмножеством плановых платежей.
- Для карт с повторным использованием (`reusable`) в день исполнения платежа пользователь вручную указывает сумму, которая возвращается в активный баланс.
- Для карт только на погашение (`repayment_only`) в день исполнения платежа пользователь вручную указывает оставшуюся к погашению сумму после списания процентов.
- Хранить кредитный лимит отдельным полем не требуется.

## Research Findings
- `src/finance_tracker/models/models.py:427` (`LoanDB`) хранит классический кредит: `amount`, `interest_rate`, `term_months`, без признака револьверности/повторного использования.
- `src/finance_tracker/models/enums.py:104` (`LoanType`) не содержит типа кредитной карты.
- `src/finance_tracker/services/loan_service.py:407` (`create_disbursement_transaction`) разрешает только одну транзакцию выдачи кредита за весь жизненный цикл займа (`disbursement_transaction_id` единственный и защищен от повторного создания).
- `src/finance_tracker/services/loan_service.py:565` (`execute_payment`) всегда создает расходную транзакцию на сумму платежа и не создает автоматически доступный к повторной трате лимит.
- `src/finance_tracker/services/transaction_service.py:38` (`get_total_balance`) считает общий баланс как `доходы - расходы`, без разделения по счетам/источникам средств.
- Тестовая инфраструктура уже настроена: `pytest`, `pytest-cov`, `hypothesis`, `pytest-asyncio`; CI прогоняет тесты с порогом покрытия 66% (`pyproject.toml`, `.github/workflows/ci.yml`).

## Preliminary Assessment
- Текущая реализация хорошо покрывает классические кредиты/займы с погашением тела и процентов.
- Сценарий револьверной кредитки (после минимального платежа часть лимита снова доступна для трат) поддержан неполно: нет доменной модели для лимита и его доступной части, нет механизма повторных "выборок" долга.

## Technical Decisions
- Источником текущего состояния по картам в этом кейсе является ручной ввод пользователя в момент исполнения планового платежа.
- Требуется разделить два режима карт:
  - `reusable`: при исполнении платежа фиксировать `returned_to_active_balance` (сумма, возвращенная в активный баланс)
  - `repayment_only`: при исполнении платежа фиксировать `remaining_debt_after_payment` (остаток к погашению после платежа)
- Для `reusable` выбрано отражение как корректировка баланса (не как обычный доход).
