# ROADMAP — Finance Tracker Flet

_Актуализировано: 2026-02-10_

## 1) Текущее состояние

- Продукт в рабочем состоянии: управление транзакциями, категориями, кредитами, отложенными платежами, плановыми транзакциями, план-факт, календарь.
- Качество кода стабилизировано: `ruff check src tests` проходит.
- Тесты стабильны: `pytest tests/ -q` проходит (899+ тестов, включая property/integration).
- CI включен: lint + тесты на GitHub Actions.
- Flet зафиксирован на совместимую ветку: `flet~=0.80.5`.

## 2) Что уже закрыто

- Миграция на современный API Flet и устранение deprecation-проблем.
- Актуализация документации по запуску, тестам и сборке.
- Базовая инженерная инфраструктура: `.editorconfig`, `ruff`, CI workflow.
- Рефакторинг и стабилизация тестового контура (регрессии и UI-cases).

## 4) План релизов

### Release A — Data Safety

- Реализация issue `#4` (экспорт/импорт end-to-end).
- Документация и UX-сообщения полностью синхронизированы с фактом.

Критерии приемки:
- Round-trip экспорт/импорт на чистой БД и предзаполненной БД.
- Понятные ошибки/отчеты без silent-failure.

### Release B — Obligations

- Реализация issue `#3` в рамках текущего экрана/механизма плановых транзакций.
- Группировка частей обязательства, расчет остатка, учет внеплановых оплат.

Критерии приемки:
- Доменная целостность в БД.
- Корректный расчет "Цель / Оплачено / Остаток" в UI и сервисах.

### Release C — Architecture & UX

- Декомпозиция крупных модулей.
- Улучшение пользовательских сценариев для ежедневного планирования и долгов.

Критерии приемки:
- Снижение сложности модулей.
- Упрощение ключевых пользовательских действий.

## 5) Принципы поддержания roadmap

- Roadmap — только стратегический документ (направления и этапы).
- Детали выполнения ведутся в GitHub Issues/PR.
- Любая новая крупная фича должна иметь issue с критериями приемки.
- При расхождении между roadmap и issue источником истины считается issue.
